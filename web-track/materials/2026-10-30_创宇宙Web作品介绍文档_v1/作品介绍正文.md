# 01 项目详情及使用方式
## 项目面向什么问题
学习、创作或小型项目筹备时，资料、想法、待办和日期经常分散在不同页面。创宇宙提供可自由组合的个人Web工作台：用户可以按自己的习惯摆放模块，用空间聚合一个主题，再用AI将已有信息整理成可审核的行动方案。

## 已实现的主要能力
| 能力 | 使用方式 |
| --- | --- |
| 搭建工作台 | 选择模块或场景模板，将方块放入真实首页画布；支持拖动、调整大小、缩放和平移。 |
| 组织主题空间 | 围绕课程、活动或创作建立空间，集中管理笔记、资料和所属待办；可搭建下级空间。 |
| 扩展个人工具 | 创建便签、清单、链接等配置型方块；代码型小程序经审核保存后，由用户手动启动。 |
| 让AI协助行动 | 查询工作区记录，生成结构化方案；用户补充修订并确认后保存结果，查看回执并按条件撤销。 |

## 本地启动
从公开仓库根目录进入应用目录，使用Node.js 22.13及以上版本。基础运行无需安装npm依赖。

```text
cd web-track/chuangyuzhou
node tools/verify-source.mjs
node tools/start.mjs --check
node tools/start.mjs
```

浏览器打开 **http://127.0.0.1:4396/**。Windows也可在应用目录双击“启动创宇宙.cmd”。首次使用，读取本实例`yuzhou/.cu-runtime/data/setup-code.txt`中的初始化口令，创建自己的账号，密码至少12字符。启用AI时配置自己的模型连接，可参考应用目录中的`.env.example`。模型Key由服务端使用，提交材料不包含真实Key。

## 一次完整的操作
**①选择与搭建**：进入搭建台，按需求加入模块或创建空间。**②积累内容**：添加资料、笔记与待办。**③提出需求**：向“小宇”描述目标与时间，先查看查询结果和行动审核单。**④修订与确认**：逐项核对名称、归属和日期，补充要求后再确认。**⑤检查结果**：进入空间、待办和日历查看，刷新核对保存状态；需要时从回执发起有限撤销。

# 02 项目亮点
:::subtitle 从“工具集合”走向用户自己组织的工作台

## 亮点一：布局和业务连接在一起
方块直接承载模块、空间或个人工具的真实入口。用户调整画布后可以进入对应页面继续工作；首页组织方式与资料、任务等业务内容相连。缩放和平移帮助用户浏览较大的工作台。

## 亮点二：用空间保留一个主题的上下文
一个读书会、创作计划或课程可以拥有自己的笔记、资料、待办和搭建画布。主题内容集中后，用户查看进展或向AI说明目标时有清晰的对象，关联待办可投影到日历。

## 亮点三：AI方案有可检查的执行过程
AI以受支持的查询和行动结构与应用协作。行动审核单呈现将要新增或修改的对象，用户可以继续修订；确认时再校验当前状态。执行后保留回执，避免重复确认带来重复新增，并为符合条件的操作提供撤销。

## 亮点四：从通用模块延伸到个人小工具
除内置模块外，用户可配置便签、清单等自定义方块，或通过AI辅助制作小程序。代码型小程序采用受限接口和隔离执行环境，保存后由用户手动运行，使个人需求可以落到可操作的工具中。

:::diagram workflow

# 03 AI技术落地使用与测试情况
## AI在项目中承担的工作
“小宇”通过服务端模型接口处理用户需求，并在合法范围内查询工作区记录。查询结果用于生成结构化行动单，覆盖空间、笔记和待办等受支持操作。用户审核、补充修订并确认后，应用执行校验、保存并提供回执。

## 真实AI场景验证
2026年10月24日，在本机Web服务和独立合成账号中，使用 **deepseek-flash** 验证读书会筹备场景。3轮用户消息产生4次真实模型请求，均返回HTTP 200；合计48,730 token（输入46,802，输出1,928）。

| 环节 | 实际结果 |
| --- | --- |
| 查询与生成 | 查询现有记录并生成行动审核单；确认前未新增业务记录。 |
| 补充修订 | 首次修订漏改待办日期；审核发现后补充指令，日期得到修正，错误方案未执行。 |
| 确认与保存 | 确认后形成1个空间、1篇笔记及2条未完成待办；刷新后保留，重复确认未重复新增。 |
| 日历关联 | 两条待办分别关联至10月27日、29日，在日历中显示。 |
| 撤销修复 | 浏览空间触发默认布局后，原撤销留下空空间；修复后以保存的真实状态完成离线浏览器回放，核对撤销结果及无关记录保护。 |

## 工程回归与验证范围
同阶段源码自动回归 **920项：917通过、0失败、3跳过**。其中27项针对性回归已包含在总数内。3项跳过对应2项可选资料解析器检查和1项可选原生移动桥接检查。

上述模型记录反映一次具体场景的运行结果。修复后的撤销结论来自离线回放；网站模式已做本地配置和同源检查，真实公网HTTPS部署尚未完成。后续可继续评估更多任务类型、不同模型及真实用户使用效果。

# 04 项目中涉及的关键技术
:::diagram architecture

| 技术环节 | 实现与作用 |
| --- | --- |
| Web界面 | HTML、CSS、原生JavaScript ES模块与hash路由，构建欢迎页、自由画布、搭建台及业务页面。 |
| 同源应用服务 | Node.js统一提供页面、认证和业务API；SQLite保存账号、会话与工作区，附件独立管理。 |
| 本地恢复 | IndexedDB保存草稿和待同步缓存；同步以状态版本校验保护不同内容，保留恢复入口。 |
| AI协作协议 | 采用应用自定义的查询与行动JSON结构，经Schema校验、状态指纹检查、预览和人工确认后执行；后台任务轮询返回结果。 |
| 行动可靠性 | 拒绝过期方案；重复确认返回已有回执且不重复写入。撤销时检查后续变化，保护已发生的人工修改。 |
| 网站访问保护 | 网站模式固定HTTPS原点，使用Secure、HttpOnly、SameSite=Strict的`__Host-`会话Cookie，配合同源及CSRF校验。 |
| 模型连接配置 | 服务端读取启动环境变量或本地配置；有效环境配置接管模型设置，接口不返回Key或其片段。 |
| 小程序隔离 | 通过隔离渲染页、Worker及受限消息接口运行；用户审核保存后手动启动，并可停止。 |

当前支持单账号的个人工作台使用；团队多租户与实时协同编辑尚未实现。资料正文解析用于提供文字上下文，当前未实现OCR和向量检索。

# 07 项目基础与本版优化
创宇宙是围绕“让每个人搭建自己的工作台”持续开发的同一作品。本Web版保留自由画布、模块组合、空间、自定义方块和AI伙伴等业务能力，进一步完善网页服务配置、模型连接、数据保护与操作可靠性。源码、开发过程和阶段测试保存在独立公开仓库中，可按提交记录核对。

| 优化方向 | 本Web版的具体工作 |
| --- | --- |
| 网页运行 | 明确本机模式与网站模式，提供固定HTTPS原点及反向代理配置参考，补充浏览器能力和运行提示。 |
| 访问保护 | 在网站模式完善会话Cookie、同源及CSRF校验，并提供启动配置检查。 |
| 模型配置 | 增加启动环境变量与.env入口，兼容设置页配置；启动时检查配置合法性，接口不返回Key或其片段。 |
| AI行动流程 | 核对查询、方案生成、多轮补充修订、确认、刷新与日历关联；保留过期及重复确认保护。 |
| 撤销可靠性 | 区分浏览产生的默认空间布局与后续人工定制，修复浏览后撤销留下空空间的问题。 |
| 运行和证据 | 完善启动说明、源码校验、阶段测试与截图，将工程结果对应到可核对版本。 |
