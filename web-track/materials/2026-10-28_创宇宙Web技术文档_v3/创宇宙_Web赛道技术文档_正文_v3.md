## 摘要
创宇宙面向个人资料、任务和日程分散，以及固定软件难以适应不同工作习惯的问题，提供模块、空间、自由画布和自定义方块。用户可以围绕学习、项目或活动筹备组织自己的工作台；AI伙伴“小宇”通过读取受支持的内容、生成结构化方案和展示修改预览，帮助用户把想法转化为可核对的业务操作。

系统使用HTML、CSS与原生JavaScript模块构建前端，Node.js统一提供页面与同源API，SQLite保存工作区状态，IndexedDB保存设备侧草稿与恢复副本。AI采用服务端DeepSeek接口与应用自定义查询、行动协议；方案经审核确认后执行，代码型小程序另需手动启动。

WEB-008自动回归共920项，917通过、0失败、3跳过。本机Web合成账号完成真实AI查询、方案生成、补充修订、确认、刷新与日历关联，4次请求共48,730 token。修复后的撤销用保存的真实状态离线回放复验。本版补充模型选型、优化依据、创新差异及案例矩阵，不新增模型调用或业务实现。[E01-E04、E13]

# 01 需求分析与功能范围

## 场景：把活动筹备放在同一工作环境
首要评审场景是个人学习者组织读书分享会或类似的小型项目：来源资料、筹备笔记、待办和日期分散，修改时需要核对它们的关联。平台仍允许每个人搭建自己的工作台，本报告先用一个明确任务解释其价值，不将单例扩展为所有用户均已受益。

创宇宙允许建立筹备空间，把资料、任务和工具放入同一工作环境，再由AI先查现有记录，生成可审阅的跨实体行动单。用户决定采用哪些模块、布局与行动。代表性闭环为“查来源→拟建空间/笔记/待办→改日期→人工确认→日历关联”，证据见第12-13页。

| 需求 | 设计回应 | 可核对的行为 |
| --- | --- | --- |
| 组织方式因人而异 | 10个内置模块、6种搭建模板 | 模块可排序或收起；收起入口保留原业务 |
| 放置与访问应直观 | 拖入画布、调整尺寸、双击进入 | 搭建位置对应真实工作台；缩放只改变视野 |
| 不同项目需要分区 | 空间与下级空间各有画布 | 使用父子关系组织内容；保留来源返回 |
| AI建议需要落实 | 查询、审核单、修订、确认与回执 | 确认前不创建业务，确认时重新检查状态 |
| 现成模块不够灵活 | 配置型方块与代码型小程序 | 用户可编辑配置；小程序显式运行 |

## 业务模块与平台能力
10个内置模块为AI伙伴、课程、英语、灵感收集箱、待办、生活回顾、记账、日历、课表和比赛。自由画布、空间、自定义方块及导航编排属于承载这些模块的平台能力。课程与课表可关联；任务日期可以投影到日历，避免重复维护同一事项。[E01、E05]

自定义方块共有7类：便签、清单、网址收藏、进度、重要日期、记录表和交互小程序。前6类以受验证的配置表达内容，最后一类用于计算器、预算或专用清单等交互需求。

## 适用范围
当前服务是单账号个人工作台，同一账号可在不同浏览器登录。设计重点是个人工作环境的组合与整理，尚未实现公众注册、多租户组织和多人实时协同编辑。本文不以模块数量推导使用收益，实际效率需要后续真人试用验证。

# 02 系统架构与技术选择

:::diagram architecture

## 同源Web应用
前端使用原生ES Modules与hash路由，不依赖前端构建步骤。Node HTTP服务同时提供页面、身份认证、工作区状态、附件和AI任务接口。基础应用没有npm运行依赖，便于从公开源码核对实际运行路径。可选Python仅承担特定文档的正文解析。[E01、E06]

| 层次 | 核心责任 | 代表实现 |
| --- | --- | --- |
| 展示与交互 | 页面、画布、模块配置、审核单 | app.js、canvas.js、builder.js |
| 业务模型 | 实体校验、关联、行动预演与撤销 | workbench-model.js、workspace-actions.js |
| 服务与AI | 认证、查询、任务编排、模型传输 | server.mjs、hermes.mjs、deepseek.mjs |
| 存储与文件 | 修订号、快照、原件、正文解析 | store.mjs、extractor.mjs |

Web模式在同机HTTPS反向代理之后运行，Node固定监听127.0.0.1:4396。页面与API位于同一原点；浏览器无需向第三方域名直接发送模型Key。该架构提供网站运行能力，真实公网部署状态另在第15页说明。

# 03 工作台模型与直接操作

## 配置、布局与业务内容分别管理
工作台配置保存标题、模块启用状态和导航位置；画布保存方块的位置与尺寸；课程、任务和笔记等业务保存内容。改变显示方式不应删除原记录，平移和缩放也不应误写为业务几何。搭建台复用真实画布，用户看到的落点就是后续工作台的位置。[E05]

| 对象 | 关键关系 | 行为约束 |
| --- | --- | --- |
| workbench | 模块配置与navigation | 工作台和搭建台保留直接入口 |
| spaces | parentId形成层级 | 主空间与下级空间分别配置画布 |
| customBlocks | spaceId确定所属空间 | 配置与私有数据分开维护 |
| timetable | courseId关联课程 | 从安排进入真实课程与资料 |
| files | blobId关联原件 | 记录引用真实附件，不拼任意路径 |

## 自由画布与导航
画布支持拖动、调整大小、网格吸附、平移、缩放及不同排列方式。卡片内容根据容器尺寸适配，用户可双击或按键进入实际页面。主空间与下级空间共享平台规则，但保留各自画布配置。业务模块作为共享入口时，不因此复制整套业务数据。

侧栏可排序并选择直接显示、更多或隐藏；模块收起与数据删除是不同操作。欢迎页根据当前合法工作台内容生成入口，点击时重新检查目标是否仍有效，避免使用过期展示中的路由。

## 关联优先于重复录入
课表通过稳定courseId进入课程；日历将待办、比赛节点和英语考试作为来源记录的只读投影，编辑返回源模块。以修改待办截止日为例，日历随同一任务更新，不自动再建一条独立日程。这使AI行动和手工操作遵循同一组业务关系。

# 04 AI行动闭环

:::diagram workflow

## 从自然语言到可检查的方案
服务端先提供工作台目录。模型可返回合法的只读查询，应用读取真实记录后继续编排；当信息足够时，模型生成回复与结构化行动单。程序校验字段、实体、引用和归属，在克隆状态中预执行，向用户展示预期变化。继续补充要求会形成新的待审核方案。[E07]

| 阶段 | 处理方式 | 保持的不变量 |
| --- | --- | --- |
| 查询 | 白名单查询返回当前记录 | 不执行任意路径、网址或外部工具 |
| 方案与修订 | 校验JSON并替换待审核版本 | 非空查询与执行方案互斥 |
| 审核 | 展示对象、字段变化及代码 | 文字回复不自动造成业务写入 |
| 确认 | 核对对话快照与工作区指纹 | 拒绝过期方案；重复确认复用回执 |
| 撤销 | 逐项对照执行后状态逆向处理 | 保护后续编辑，必要时保守保留 |

## 行动范围
当前行动机制只允许已注册实体的新建、修改、归档和恢复，一次1-50项。程序拒绝未知字段、任意属性路径、模型自行指定新记录ID及不合法的前序引用。执行在克隆状态中完成校验，保存失败时恢复；回执记录前后快照，为后续核对与撤销提供依据。

这套闭环把“生成一段建议”和“修改真实工作区”连接起来。用户保留审核决定权，模型输出仍可能有业务错误，不能由HTTP成功或结构合法直接推定内容正确。

WEB-008修复了浏览空间后默认workbench被误判为定制布局的问题。撤销通过真实布局生成器重建默认预设，逐项核对卡片ID、顺序、位置、尺寸和颜色；自动预设可随创建撤回，后续搭建、视角、设置和业务修改仍受保护。[E07、E13]

# 05 模型接入与上下文组织

## 服务端模型适配
当前启动入口使用DeepSeek直连接口，服务端POST至 `https://api.deepseek.com/chat/completions`。传输采用JSON模式、stream:false，单次超时上限180秒，响应体上限1MiB。应用支持的模型标识包括deepseek-flash、deepseek-v4-pro、deepseek-chat和deepseek-reasoner，默认deepseek-flash；可用性仍取决于供应商和账号。[E08]

当前编排使用应用自定义queries与proposal协议，供应商原生tool_calls或function_call响应会被拒绝。因此这里的工具机制是应用级结构化查询与行动解释，不宣称已接入MCP或供应商原生Function Calling。AI任务在后台运行，前端每2.5秒轮询状态，当前没有SSE或WebSocket流式输出。

| 约束 | 当前上限或机制 | 目的 |
| --- | --- | --- |
| 底层请求 | 每次编排最多5次 | 防止无界循环；一次发送可能多次调用 |
| 查询迭代 | 最多3轮，每轮最多6项 | 按需要读取实际工作区内容 |
| 格式修正 | 最多1次 | 修正格式并继续保留结构校验 |
| 附件正文 | 单文件最多60,000字符 | 限制解析与上下文体积 |
| 用户与附件文字 | 总量上限100,000字符 | 超限提示；不声称无限知识库 |

## 正文抽取与结构化查询增强
TXT、Markdown和CSV通过Node读取；DOCX、PPTX和文字PDF通过可选解析器提取正文。查询覆盖搜索与详情、日期范围、周课表、收支汇总和已有附件正文。file.read仅接受已保存或当前对话附件的真实blobId。修改已有方块配置或私有数据前，需要本轮完整读取，截断或失败结果不能用于整包替换。

当前没有向量库、embedding、语义召回、OCR和图片理解。AI使用时，相关用户输入、合法查询结果和附件提取文字会发往模型供应商。产品目前不保存供应商usage；本次用量由独立验收捕获器从真实响应提取白名单计数，不记录Key、请求头或settings。[E13]

# 06 AI选型理由与优化依据

## 模型选择与设计取舍
本版选择已实现的DeepSeek服务端适配器，默认deepseek-flash。理由是现有传输层能与应用的JSON协议、超时和校验流程衔接，且WEB-008取得了可复核的真实返回。模型传输与业务执行分离，业务实体不直接依赖供应商返回格式之外的工具执行权限。[E07、E08、E13]

这是一项与当前实现相匹配的选择，未做不同供应商或模型的横向比较。本文不将默认模型称为成本最低、速度最快或准确率最高；可用性仍由供应商与账号决定。

| 设计选择 | 优化目的与取舍 | 已有证据及限度 |
| --- | --- | --- |
| 合法目录与按需查询 | 先定位真实记录，控制无关上下文；不让模型拼任意路径 | 本次有search查询结果进入下一次模型输入；没有上下文节省比例对照 |
| JSON模式与schema校验 | 将自由回复转为可预演字段；结构合法仍不等于业务正确 | 首次修订日期漏改被审核发现，错误方案未确认 |
| 有界迭代与格式修正 | 最多3轮查询、5次请求和1次格式修正，限制循环与失败扩散 | 工程回归覆盖上限；本次实际4次调用，无额外格式修正 |
| 指纹核对与人工确认 | 过期方案拒绝；真实写入前由人核对对象和关系 | 旧方案409、确认前无业务新增、重复确认不重复创建 |
| 快照回执与有限撤销 | 对照执行后状态处理撤回，保护后续人工改动 | 默认布局修复后离线回放通过；不承诺任意修改都能无损撤销 |

## 成本与效果证据如何解释
本次共4次请求、48,730 token。供应商报告输入缓存命中29,824、未命中16,978；这只是该场景的用量，不是应用主动缓存优化的对照实验，也不换算为未经账单核对的费用。[E13]

现有优化主要服务于可控性、可解释性及失败保护。若要报告准确率、节省时间、上下文下降或成本优势，需要独立任务集和比较实验；本版尚未提供这些结论。

# 07 自定义方块与交互小程序

:::diagram miniapp

## 两层扩展机制
配置型方块用明确字段表示便签、清单、表格和进度等内容；代码型方块允许生成新的计算和交互逻辑。代码先进入审核与预览，确认保存后仍由用户单独点击运行，刷新页面不会自动启动。方块配置与私有数据分别管理，代码更新应保留已经填写的有效数据。[E09]

| 控制点 | 当前实现 |
| --- | --- |
| 隔离执行 | iframe仅allow-scripts，不授予allow-same-origin；代码在专用Worker运行 |
| 受控接口 | app.render、app.onEvent、app.getData、app.setData |
| 显示与数据 | 可信页面渲染白名单组件树；通过JSON桥处理本方块数据 |
| 通信校验 | 核对来源窗口与随机token，限制消息和调用频率 |
| 生命周期 | 消息上限64KiB；停止、离开或4秒心跳无响应后清理 |
| 网络约束 | 运行页CSP限制connect-src，Worker屏蔽网络及相关接口 |

## 可预览、可重试，也需要审核
草稿预览使用临时状态，取消预览不应把试填内容写入正式记录。运行失败和停止后可重新启动；宿主保留超时终止与错误提示。当前提供的是浏览器内的受控运行器，没有授予任意系统执行、依赖安装或外部软件操作能力。

生成代码可能出现接口误用或业务计算错误。历史DEV-028预算案例曾在首次运行时报错，后续修订才完成验证；WEB-008没有重新验收代码型小程序。运行器约束不能替代业务审核，也不等同独立操作系统沙箱或外部安全认证。[E12]

# 08 持久化、同步与文件

:::diagram sync

## 单账号快照与修订号
SQLite实际保存account、sessions、workspace、workspace_history、files和auth_attempts等表。课程、任务、空间与画布等业务主要位于工作区JSON中，不是每种业务各一张关系表。写入以baseRevision进行乐观锁检查，旧版本返回409，避免静默覆盖新内容。[E06、E10]

浏览器IndexedDB保存账号隔离的工作区缓存、待同步状态、草稿和恢复副本。内容冲突时保留本机副本，并提供导出与加载远端路径。旧缓存迁移需等待事务完成和读回核对；如果旧窗口期间又有修改，不能直接释放旧数据。保存失败仍保留脏数据并显示重试状态。

## 原件与正文分开保存
附件元数据保存于SQLite，原件位于当前实例的files目录，通过blobId关联。上传以流式SHA-256核对内容，临时文件独占创建，内容冲突拒绝写入。单文件上限40MiB，工作区JSON上限12MiB；正文抽取结果不替代原件。[E06]

| 文件类型 | 运行条件 | 支持边界 |
| --- | --- | --- |
| TXT / MD / CSV | Node内建 | 有界文本读取 |
| DOCX / PPTX | 独立Python ≥3.10 | 标准库提取正文；不支持旧DOC/PPT |
| 文字PDF | Python及锁定pypdf | 可提取文字；不提供OCR |

本Web阶段两项解析相关检查因独立Python解析器未配置而跳过。上述内容描述源码能力和配置条件，不当作本次全部格式已实测。

# 09 Web访问与安全边界

## 显式网站模式
默认local模式保留本机访问。web模式必须配置完整HTTPS原点，拒绝用户名、路径、查询、片段及异常原点；Node仍仅监听127.0.0.1:4396。应用不从Forwarded等代理头推断可信域名。浏览器启动先检查安全上下文、UUID、文件哈希与存储能力，不满足时给出明确提示。[E02、E11]

| 边界 | 机制 | 作用 |
| --- | --- | --- |
| 账号与会话 | scrypt密码哈希；会话token只存哈希 | 服务端验证，不将口令当作公开配置 |
| 网站Cookie | __Host-前缀、Secure、HttpOnly、SameSite=Strict、Path=/，无Domain | 限制传输和脚本读取，避免域Cookie扩散 |
| 写操作 | 固定HTTPS Origin与CSRF token | 拒绝跨源写入与伪造代理信任 |
| 响应与页面 | HSTS、CSP及no-store | 限制资源与缓存行为 |
| 公开路径 | 仅提供前端和受控API | 不将后端、配置及私有运行目录作为静态站点 |

## 模型Key配置
