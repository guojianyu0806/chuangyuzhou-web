# 01 项目详情及使用方式
## 要解决的问题
准备读书会时，资料、提纲和待办往往分散在几个页面。创宇宙把这些内容放进同一个空间，首页还能按自己的习惯摆放入口。需要补一份提纲或调整待办时间时，可以让小宇先列出建议。

## 已实现的功能
| 功能 | 怎么用 |
| --- | --- |
| 搭建首页 | 选模块或场景模板，把方块放上画布。可拖动、调大小、缩放和平移。 |
| 整理同类内容 | 在空间里放笔记、资料和待办，可建下级空间。卡片多时，勾选它们，请 AI 建议主题。 |
| 添加个人工具 | 配置便签、清单、链接等方块。代码型小程序经审核保存，由用户手动打开。 |
| 查询和安排 | 小宇根据工作区记录列出建议。核对后保存，可查回执，符合条件的操作可撤销。 |

## 本地启动
将源码 ZIP 解压。从仓库根目录进入应用目录，使用 Node.js 22.13 或更高版本。基础页面无需另装 npm 依赖和模型 Key。

```text
cd web-track/chuangyuzhou
node tools/verify-source.mjs
node tools/start.mjs --check
node tools/start.mjs
```

浏览器打开 **http://127.0.0.1:4396/**。Windows 也可双击「启动创宇宙.cmd」。首次启动，使用 `yuzhou/.cu-runtime/data/setup-code.txt` 中的本机初始化口令创建账号，密码至少 12 字符。需要试用 AI 时，请按 [本版启动指南](https://github.com/guojianyu0806/chuangyuzhou-web/blob/a3d10a0b0d98ea390e62e28073efef1000b93dc0/web-track/chuangyuzhou/README.md) 配置自己的 DeepSeek Key。材料中的配置模板保留空值。

## 用读书会走一遍
进搭建台放一个空间，添加笔记和待办。请小宇按现有资料列出准备事项。确认前，在审核单上核对名称、归属和日期。保存后打开空间、待办和日历检查结果，再刷新页面复查。

# 02 项目亮点
## 拖动方块就能调整首页
课程、空间和个人工具都可以放在首页。点一下方块，就能直接打开对应的页面。动手调整布局时，原来的笔记和待办仍留在各自的空间里。

## 卡片可按主题查找，也可收进盒子
勾选要整理的卡片，用户可以修改 AI 建议的主题。确认后，主题名会出现在画布上。需要腾出画布时，可把指定卡片拖进收纳盒，需要时再拖出来。

## 日期在审核单上改好，再保存
小宇提出新增或修改建议，用户可以补充要求。确认时应用检查工作区有没有变化。执行后可以查回执，重复确认沿用原回执。准备撤销时，应用会检查后续修改，避免覆盖用户之后改过的内容。

## 用户可以加自己的便签和清单
便签、清单、链接都可作为方块。还可以请 AI 辅助制作小程序。代码保存前需要审核，保存后由用户手动在隔离环境中运行。

# 03 AI 技术落地与测试
## 小宇怎样读记录和提出建议
小宇先从当前工作区查询本次任务需要的记录，再按约定的 JSON 结构列出建议新增或修改的空间、笔记和待办。用户可以先改方案，确认后应用校验、保存，并给出回执。

## 真实 AI 案例
2026 年 10 月 24 日，用本机 Web 服务、隔离测试账号和合成数据试做一次读书会筹备。3 轮用户消息触发 4 次 **deepseek-flash** 请求，均返回 HTTP 200。共使用 48,730 token（输入 46,802，输出 1,928）。

| 环节 | 实际结果 |
| --- | --- |
| 生成建议 | 查询已有记录，生成行动审核单。确认前没有写入业务记录。 |
| 修订日期 | 第一次修订漏改了一条待办日期。补充指令后改正，错误方案没有执行。 |
| 确认与保存 | 新建 1 个空间、1 篇笔记和 2 条未完成待办。刷新后保留，重复确认没有新增记录。 |
| 日历关联 | 两条待办分别出现在 10 月 27 日和 29 日。 |
| 撤销修复 | 曾出现撤销后留下空空间的问题。修复后，用留存的真实状态做离线浏览器回放，复核撤销结果及无关记录。 |

## 归类与最新回归
11 月 10 日，DeepSeek 把「校园创作展筹备」空间和「布展前核对」清单归到一起，将「个人阅读记录」分到书单。只发了三张选中卡片的编号、标题、类型和简介，这一次共 360 token。我们把清单的主题改为「校园创作展现场筹备」，跳过阅读卡。刷新时审核草稿仍在。确认后再刷新检查分组，最后撤销。

11 月 15 日，用隔离 Edge 和模拟建议核对了画布主题标签。在 390 像素宽的视口中检查了「找盒子」和「适应全部卡片」。另做了慢启动、慢登录及超时恢复测试。自动回归共 951 项，948 项通过，3 项跳过，0 项失败。

# 04 项目中涉及的关键技术
:::diagram architecture

| 技术环节 | 实现与作用 |
| --- | --- |
| Web 界面 | HTML、CSS、原生 JavaScript ES 模块和 hash 路由，提供首页画布、搭建台和业务页面。 |
| 同源应用服务 | Node.js 提供页面、登录和业务 API。SQLite 保存账号、会话和工作区，附件另存。 |
| 本地恢复 | IndexedDB 保存草稿与待同步缓存。同步时检查数据版本，保留恢复入口。 |
| AI 查询与行动 | 模型返回约定格式的 JSON，应用检查字段和当前数据，再把建议交给用户确认。后台任务经轮询返回结果。 |
| 确认与撤销 | 过期方案不能确认。重复确认返回已有回执。撤销时检查后续变化，保护之后的人工修改。 |
| 网站模式 | 固定 HTTPS 原点。会话 Cookie 设为 Secure、HttpOnly、SameSite=Strict，配合同源和 CSRF 校验。 |
| 模型连接 | 服务端读取启动环境变量或本地配置。有效环境设置优先，接口不回传 Key 或其片段。 |
| 小程序运行 | 在隔离渲染页和 Worker 中用受限消息接口运行。审核保存后由用户启停。 |

当前供个人账号使用，未实现团队实时协同。可读取资料正文作为文字参考，未实现 OCR 和向量检索。

# 07 项目基础与本版优化
创宇宙在原有画布、空间、自定义方块和 AI 审核的基础上，完善了 Web 启动、登录保护和模型配置。这次根据评审意见，重点改了加载等待和卡片查找。

| 评审意见 | 改动与验证 |
| --- | --- |
| 增加页面加载优化 | 静态资源压缩并校验缓存，课程、英语和备份按需加载，提前请求共享提示脚本。预加载阶段在模拟 60 毫秒延迟、约 12 Mb/s 的环境下交替测试 12 对，预加载版首开在 12 对中有 10 对更快，配对差值的中位数是快 90.2 毫秒。当前版另测了慢启动、慢登录、超时重试及缓存恢复。 |
| 内容多时用 AI 分类 | 可勾选卡片、修改建议、确认和撤销。主题出现在画布标签上，整理后的卡片可手动拖进收纳盒。第 4 页记录真实模型用例，第 8 页展示模拟建议的复验画面和拖动录像。 |
