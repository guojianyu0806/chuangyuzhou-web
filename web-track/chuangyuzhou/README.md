# 创宇宙

**让每个人搭建自己的工作台。** 创宇宙是一款可组合的个人工作台：用模块、空间和方块组织资料、日程与任务，由AI伙伴协助查询、提出方案，在用户审核确认后执行。

第九届传智杯AI WEB网页开发挑战赛（10037）· 材料修正 WEB-010 · 2026-10-28。业务实现及撤销修复基准为 `c71c0411245943198ce1db9d6276e211b4a28c94`（WEB-008）；本轮统一运行指南与评审说明，不改变业务功能。当前应用文件清单见 `SOURCE-MANIFEST.json`，阶段改动见 `RELEASE-CHANGES.json`。

## 评审路线

1. 从[最新材料索引](../materials/README.md)进入技术PDF，查看需求、架构、AI选型依据、创新点及证据定位。
2. 阅读[WEB-008真实AI流程](../evidence/WEB-008.md)：查询来源、生成审核单、补充修订、确认执行、刷新及日历关联均有实际记录；首次修订漏改日期、审核保护和修正过程保留。
3. 对照[固定业务源码](https://github.com/guojianyu0806/chuangyuzhou-web/tree/c71c0411245943198ce1db9d6276e211b4a28c94/web-track/chuangyuzhou)及回执核对实现。修复后的撤销使用保存的真实状态离线回放，另行标识，未冒充新在线调用。
4. 需要亲自操作时，按第2节启动，再按第3、5节配置自己的模型连接。当前没有已部署的公网体验站点或预配置评审账号。

AI是把自然语言需求落实为工作区操作的核心流程：**读取已有内容 → 生成行动审核单 → 补充修订 → 人工确认 → 保存回执与关联结果**。凭据由使用者选择配置；未配置Key时仍能查看和手工使用工作台，但不能执行真实模型请求。

## 主要功能

- 自由画布、拖入搭建、尺寸调整、侧栏排序，以及主空间与子空间各自的画布。
- 课程、英语、灵感、待办、回顾、记账、日历、课表、比赛及AI伙伴等可选模块；课程与课表关联、账单分类和草稿恢复。
- 自定义便签、清单、表格等方块，以及先审核保存、再手动启动的代码型小程序。
- AI查询、方案生成、多轮修订、确认执行和有边界撤销；未配置模型时不伪装AI已连接。

创宇宙是一款AI驱动的可搭建个人Web工作台。前端采用HTML、CSS和原生JavaScript模块；Node.js提供认证、SQLite存储、查询、文件解析与模型接入。项目与版本说明见 `SOURCE-NOTICE.md`；内部 `yuzhou` 目录、数据库及备份标识保持兼容。

## 2. 快速基础运行

前提：已安装符合要求的Node。进入当前应用目录执行以下命令；后续源码ZIP应解压到新的普通可写目录，保留已有环境：

```powershell
node --version
node tools/verify-source.mjs
node tools/start.mjs --check
node tools/start.mjs
```

也可双击本目录的 **启动创宇宙.cmd**。默认访问 **http://127.0.0.1:4396/**，保持服务终端运行。校验成功会输出`check: passed`；`--check`本身不启动服务。

1. 首次打开出现“建立你的工作台”。用本机文本编辑器打开`yuzhou/.cu-runtime/data/setup-code.txt`，将初始化口令填入页面；不要把口令发给他人或放入提交材料。
2. 自选账号名和至少12字符的密码，创建账号。新账号不携带作者的资料或账号。
3. 在搭建台选择模板或模块，进入待办创建“准备读书分享会”，等待保存成功后刷新核对。
4. 在服务终端按Ctrl+C停止，再运行同一个启动命令；用刚创建的账号登录，核对任务仍在。

数据保存在本目录自己的`yuzhou/.cu-runtime/`。Web入口使用独立登录Cookie与固定4396端口，浏览器存储依照origin隔离。不要把当前使用中的账号导出包当作参赛源码。

基础运行不要求API Key，也不会自动调用付费模型。本版没有独立环境复现计时，不承诺固定耗时。环境变量的建立过程见[WEB-002](../evidence/WEB-002.md)，独立目录建立过程见[WEB-001](../evidence/WEB-001.md)；最新实际验收范围见[WEB-008](../evidence/WEB-008.md)，历史结果保留各自版本归属。

## 3. 环境变量模板

`.env.example`是可用模板，`tools/start.mjs`读取本目录`.env`；没有`.env`时采用相同默认值。需要显式保存本机配置时执行：

```powershell
if (Test-Path -LiteralPath .env) { throw '已有配置，请保留并直接编辑' }
Copy-Item -LiteralPath .env.example -Destination .env -ErrorAction Stop
```

| 字段 | 默认与范围 |
| --- | --- |
| CZB_YUZHOU_HOST | 固定为127.0.0.1；Web模式由同机反向代理提供网站入口 |
| CZB_YUZHOU_PORT | 固定为4396；端口被占用时保留其他服务并检查冲突 |
| CZB_YUZHOU_MODE | 默认local；配置为web后启用HTTPS网站模式 |
| CZB_YUZHOU_PUBLIC_ORIGIN | 默认空；web模式必须提供自己的HTTPS原点，不含路径、查询或片段 |
| DEEPSEEK_API_KEY | 默认留空；填写本Web环境专用Key后由环境配置接管模型连接 |
| DEEPSEEK_MODEL | 默认deepseek-flash；支持deepseek-v4-pro、deepseek-chat、deepseek-reasoner |

在本机编辑新建的 `.env`，填写 `DEEPSEEK_API_KEY`，按需要选择 `DEEPSEEK_MODEL`，保存后启动或重启工作台。模板中的Key保持空白；真实Key可通过启动环境变量传入，或保存在被Git忽略的本实例 `.env`，不得进入源码、截图、文档或公开提交。WEB-008使用本次专用凭据在测试进程内存中完成真实调用，测试进程结束后关闭，见[用量与凭据边界](../evidence/WEB-008.md#用量与凭据)。默认local模式保持本机使用；网站模式的配置、反向代理与上线验收见[Web服务指南](web-deployment/README.md)。

配置一行一个 `名称=值`，不加引号，不使用变量替换、表达式或行内注释。Key须为12至500个不含空白的可打印ASCII字符。未知字段、重复字段及非本入口端口会被拒绝，错误信息不会回显配置值。

也可由当前启动终端设置两个模型环境变量，以及`CZB_YUZHOU_MODE`和`CZB_YUZHOU_PUBLIC_ORIGIN`。同名变量优先级为：**启动终端 > 本目录 `.env`**；Key有效时，环境配置优先于设置页保存的连接。终端中显式设置空Key会覆盖文件Key。空Key视为未启用环境连接，仅有模型名不会改动原本机配置。启动器继续拒绝继承其他应用密钥、引擎目录和数据路径；监听地址和端口保持固定。

环境连接在启动时读入并仅保存在服务端内存，不写入 `ai/model-config.json`，状态接口不返回Key或任何片段。设置页会显示“由启动环境配置”，禁用Key、模型和保存按钮；直接调用保存或清除接口也会被拒绝。修改后需要重启。移除或清空有效环境Key并重启后，原设置页配置仍保留并恢复可用。

`config/model-settings.example.json`与`config/extractor-config.example.json`仅为字段参考，不自动加载。未启用环境连接时仍可通过登录后的“偏好与连接”配置模型；解析器使用下一节命令生成自己的配置。

## 4. 可选文档解析

在包根目录用独立虚拟环境配置，不修改全局Python：

```powershell
python --version
python -I -m venv yuzhou/.cu-runtime/extractor-venv
& .\yuzhou\.cu-runtime\extractor-venv\Scripts\python.exe -I -m pip --isolated install --only-binary=:all: --require-hashes -r requirements-extractor.txt --cache-dir .\yuzhou\.cu-runtime\pip-cache
$extractorPython = (Resolve-Path .\yuzhou\.cu-runtime\extractor-venv\Scripts\python.exe).Path
node scripts/configure-yuzhou-extractor.mjs --python "$extractorPython"
```

重启服务后上传带正文的DOCX/PPTX/PDF，检查原件下载与正文提取。只需要DOCX/PPTX时可跳过pip安装。扫描件和加密PDF不保证可解析，旧DOC/PPT不支持。替换已有解析配置前保留旧配置并明确使用脚本的`--replace`。

## 5. AI核心流程与评审操作

真实模型执行需要网络、有效Key及供应商可用额度。按第3节配置启动环境Key，或在未启用环境连接时，通过登录后的“偏好与连接”填写自己的专用Key与受支持模型。默认模型为 `deepseek-flash`，实际可用性取决于供应商与账号。选择是否配置凭据不改变AI在产品中的核心定位；启动、配置检查和查看状态不会自动调用模型。

可自行尝试以下合成输入，实际输出仍需逐项审核；它是操作示例，不作为新增验收结果：

> 先查询是否已有“读书会评审示例”空间。如果没有，请拟建该空间，在其中创建一篇筹备说明笔记，并关联两项未完成待办：2026-11-06收集资料、2026-11-07整理提纲。只给完整审核单，先不要执行，也不要修改其他记录。

| 步骤 | 操作与预期检查 |
| --- | --- |
| 查询与生成 | AI读取合法范围内的已有记录，返回方案；同名空间已存在时应先核对，避免盲目重复创建。 |
| 审核 | 若为空白合成环境，预期审核单含1空间、1篇笔记、2项关联待办；此时业务尚未创建。核对名称、日期、归属及未完成状态。 |
| 补充修订 | 例如要求“把整理提纲改到2026-11-08，其余保留，仍先不要执行”；重新核对完整方案，不能只相信回复文字。 |
| 确认与结果 | 点击确认后检查执行回执、空间笔记、两项待办及日历日期；刷新检查保留。 |
| 有限撤销 | 在未手工修改新增内容时可尝试撤销；后续编辑应保留。已完成的修复验证来自保存真实状态的离线回放，范围以WEB-008为准。 |

既有WEB-008真实验收共4次供应商请求、48,730 token，覆盖查询、生成、补充修订、确认、刷新与日历关联；第一次修订漏改日期的错误审核单未执行。浏览后撤销缺陷修复后的复验为离线浏览器回放，0新增模型调用。一个真实场景不表示所有任务稳定通过，工程通过数也不是AI准确率。

代码型小程序保存后仍需单独点击运行；WEB-008没有重新验收代码型小程序。模型额度由使用者自行准备，运行命令和文档核验均不会代为自动调用付费模型。

## 7. 常见问题

| 问题 | 处理 |
| --- | --- |
| node或SQLite不可用 | 检查Node最低版本并重新打开终端 |
| EADDRINUSE | 保留原有服务，检查4396端口冲突，不停止不明进程 |
| 初始化口令无效 | 使用当前解压副本的口令；已有账号直接登录，不重建数据库 |
| 源码校验失败 | 解压新的完整副本比较，不覆盖已使用的数据 |
| 文档解析不可用 | 配置独立Python并重启；扫描PDF不支持OCR |
| AI未接入或请求失败 | 检查自己的模型配置、额度与网络，按界面提示重试 |
| 显示本机连接失败 | 重新运行“启动创宇宙.cmd”，检查地址与端口 |

安全与兼容边界：支持本机模式与HTTPS反向代理下的Web服务配置；当前未部署公网，未验真实TLS或Linux服务安装，也不提供安卓安装包；没有独立真人收益试验、完整真机兼容或外部安全审计结论。“宇宙”与“创宇宙”为同一项目；早期快照补录的性质明确标注，不把工程核查作为赛事资格认可。
