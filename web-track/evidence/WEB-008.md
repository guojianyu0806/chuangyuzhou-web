# WEB-008 · Web真实AI验收与撤销修复

## 结论与环境

在本机浏览器及真实HTTP/SQLite服务完成查询、生成审核单、跨轮修订、确认、刷新、笔记/待办关联与日历投影。真实模型为`deepseek-flash`，通过生产`createDeepSeekRunner`向DeepSeek官方接口发送请求，没有替换供应商响应或手工制造模型方案。

本轮发现并保留两项问题：模型第一次修订漏改待办日期，经一次明确补充后修正；仅浏览新空间后撤销会误留空空间，已修复，并使用本次真实结果保存的确认后状态完成离线浏览器复验。修复后没有追加模型调用，因此不把修复后的回放写成一次新的在线模型验收，也不宣称模型首次修订成功或所有场景稳定通过。

在线阶段源码为`e5925b3b622977b6b70797ec249251983bdbba70`。使用本仓库前后端和自己的`.cu-runtime/tests-temp/WEB-008-*`新合成数据目录，监听`http://127.0.0.1:4396`，独立合成账号。此为Web源码在本机HTTP环境的功能验收，不代表公网HTTPS/TLS、真机或真人收益验收。未复制其他实例的账号、数据、附件或凭据。

## 实际流程

1. 初始化合成来源资料，以及不可改的空间/笔记、待办与日历记录。首个快照为[01-before-ai.json](WEB-008/01-before-ai.json)。
2. 从正常AI页面要求查询读书会资料与同名空间，再拟建空间、筹备说明笔记、两项关联待办。模型实际完成一轮查询，两个结果进入下一次模型输入；第一轮合计2次供应商请求。待确认时业务记录没有新增，见[首次审核单](WEB-008/02-first-proposal.json)。
3. 同一对话要求第二阶段由10月28日改为10月29日并补充笔记。第3次供应商请求只改了空间说明和笔记，待办仍为28日；完整失败保留在[首次修订](WEB-008/03-revised-proposal.json)。未确认该错误方案。此时对旧job确认，实际返回409 `STALE_PROPOSAL`，没有业务写入。
4. 正常页面补充明确修订，第4次供应商请求使空间说明、笔记与第二项待办三处均为29日，第一项待办仍为27日；[最终审核单](WEB-008/04-corrected-proposal.json)保留完整4项创建动作与注意事项。
5. 点击正常界面“确认执行这4项操作”，创建1空间、1笔记及2项未完成待办。检查真实ID与所属关系、刷新保留、空间笔记/待办页面及日历27日/29日自动关联。再次确认没有重复写入或新增模型请求，见[确认](WEB-008/05-confirmed.json)、[重复确认](WEB-008/06-duplicate-confirm.json)、[刷新及关联](WEB-008/07-refreshed-and-linked.json)。
6. 原版正常页面撤销后笔记和待办消失，但浏览自动生成的空间workbench被当成了定制画布，导致空空间保留；刷新仍如此。见[原撤销结果](WEB-008/08-undone.json)与[刷新结果](WEB-008/09-undone-after-refresh.json)。
7. 修复后，另建无Key、无供应商transport的本机合成回放服务，通过正常workspace API载入第5步的精确业务状态及回执。正常UI撤销并刷新，4项新增业务及该空间的内部自动boards全部清除，6条对话消息、来源资料及保护记录保留。见[回放前](WEB-008/10-replay-before-undo.json)、[撤销后](WEB-008/11-replay-undone.json)、[刷新后](WEB-008/12-replay-undone-after-refresh.json)。该阶段模型请求为0。

所有阶段的无关保护记录逐项完全相同。主画布仍保留已删除空间的一条隐藏几何缓存，现有显示逻辑会过滤不存在的空间；本轮没有将其写成“所有内部画布数据完全无残留”。空间本体、所属笔记/待办及空间内部自动布局已撤回。
